1 · What is MCP, in plain English

30 seconds
MCP = Model Context Protocol
An open standard (introduced by Anthropic, the makers of Claude, and now adopted across the AI industry) that lets any AI assistant connect to outside tools and data — securely, in one common language.
Think of MCP as the USB-C of AI.
One port. Any AI plugs into any tool. Before MCP, every AI ↔ tool connection was a custom, one-off integration. With MCP, you build ONE server and every MCP-capable AI (Claude, Cursor, and a growing list) can use it.

2 · Without it vs with it

why everyone adopted it
❌ Before MCP
Every app builds a custom integration for every AI. N tools × N assistants = an explosion of brittle one-off connectors. Most tools simply never get connected.
✅ With MCP
A tool exposes one MCP server. Any compliant AI discovers its tools automatically and calls them. Build once → reachable from every AI surface your clients already use.

3 · What K.I.N.D has built

live today on api.get-kind.com
K.I.N.D has its own MCP server. Discovery at GET /mcp/tools (+ /.well-known/mcp.json), execution at POST /mcp/call. It exposes our agents as callable tools:
milla_ask LIVE
Ask Milla anything from inside Claude or Cursor — business questions, document drafts, ops help. Real Claude-powered answers, in Milla's voice.
figsy_suggest_campaign LIVE
Describe a target → FIGSY returns a campaign name, 3 subject-line options and the rationale — without opening the portal.
figsy_find_leads STUB — needs key auth
Search the PDL + Hunter lead sources by industry / title / size / country from chat. Tool is discoverable today; returns a pointer to the portal until per-client API-key auth is enforced.
figsy_get_campaign_stats STUB — needs key auth
Live campaign numbers (sent · replies · meetings) in chat. Same gate: ships when key auth is wired.
Honest status: 2 of 4 tools answer for real today; 2 are discoverable stubs awaiting per-client API-key enforcement (the keys system already exists — /dashboard/developer). That wiring is the main MCP build remaining.
