## Risk

There are three real risks, all manageable:

**1. Dark mode state persistence — low risk, known solution**
Dark mode needs to remember the user's preference. The standard approach is `localStorage` + a class on `<html>`. The only gotcha is a flash of the wrong theme on page load (FOUC). Fix is a one-line inline script in `<head>` that runs before React hydrates. Completely standard, well-documented.

**2. Every component needs dark mode classes — medium effort, low risk**
Tailwind dark mode means every `bg-white` needs a `dark:bg-gray-900`, every `text-gray-900` needs a `dark:text-white`, etc. This is the bulk of the work. It's tedious, not technically risky. If we miss a spot, the worst case is one card looks wrong in dark mode — not a breakage.

**3. The dashboard restructure touches shared components — low risk**
`StatCard`, `ProductCard`, `Sidebar` are used in multiple places. Any change to them affects every page that uses them. But these components are small and self-contained — easy to audit. No database changes, no API changes, no auth changes involved.
