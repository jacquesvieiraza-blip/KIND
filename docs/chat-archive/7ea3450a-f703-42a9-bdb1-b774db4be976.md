## PIECE 3 — REAL-TIME ACTIVITY FEED

**The vision:** Live sidebar feed. "FIGSY sent 12 emails. 2 replies. 1 interested."

**How it actually gets done:**

Two approaches. Pick one based on scale:

**Option A — Polling (simple, today's tech):**

**Option B — WebSockets (real-time, future scale):**

## PIECE 5 — VISUAL AUTOMATION BUILDER

**The vision:** "When lead = Interested → create HubSpot deal → notify Slack → pause FIGSY sequence." No code.

**How it actually gets done:**

This is the most complex piece on the list. Don't underestimate it. But it's also the highest value — it's what separates a good tool from a platform.

**The architecture:**
1. **Triggers** — things that can start an automation: lead status changes, reply received, credit balance drops below X, ICP run completes, campaign paused
2. **Actions** — things that can happen: create HubSpot deal, send Slack notification, send email, pause/resume campaign, run ICP, add credits (manual review gate), webhook to custom URL
3. **Conditions** — if/then branching: if score > 80, if industry = Fintech, if country = Nigeria

**The builder UI:**
Nodes and edges. Each trigger is a node. Each action is a node. Lines connect them. This is a **React Flow** problem — it's the library Linear, Retool, and n8n use. It handles the visual canvas, drag-and-drop nodes, and edge connections. The hard work is the execution engine, not the UI.

**The execution engine:**
Automations are stored as JSON in a `client_automations` table. When a trigger fires (e.g., lead status update), the API checks if any automation is listening to that trigger for that client, evaluates conditions, and executes actions in sequence.

**What's needed:**
1. `client_automations` table — stores trigger type, conditions JSON, actions JSON, enabled/disabled
2. Trigger hooks in existing API routes (status change, reply classification, ICP run complete)
3. Action executors (HubSpot API call, Slack webhook, internal FIGSY action)
4. React Flow canvas for the builder UI
5. Node library (drag from palette onto canvas)
6. Save → validates → activates automation

**Build time:** 2–3 weeks for a solid V1. This is a significant investment.

**Trigger to start:** After 50+ clients. The value compounds with client count because each client's automation recipes become reusable templates for others.

## PIECE 8 — THE ICP THAT LEARNS ITSELF

**The vision:** After 3 months of data, FIGSY tells you which ICP criteria are actually converting.

**How it actually gets done:**

**The data already exists.** `figsy_replies` has `reply_classification` (interested/not_now/opt_out). `leads` has `industry`, `country`, `company_size`, `seniority`, `job_title`. Join them and you have a conversion rate per attribute.

**The analysis:**
```sql
SELECT 
  l.country,
  l.industry,
  l.seniority,
  COUNT(*) as total_leads,
  COUNT(CASE WHEN r.reply_classification = 'interested' THEN 1 END) as interested,
  ROUND(100.0 * COUNT(CASE WHEN r.reply_classification = 'interested' THEN 1 END) / COUNT(*), 1) as conversion_rate
FROM leads l
LEFT JOIN figsy_replies r ON r.lead_id = l.id
WHERE l.client_id = $clientId
GROUP BY l.country, l.industry, l.seniority
HAVING COUNT(*) >= 10
ORDER BY conversion_rate DESC
```

Claude reads this output and writes a plain-English insight. That's the "ICP intelligence" feature.

**What's needed:**
1. A `GET /icps/intelligence` endpoint — runs the query above, passes results to Claude Haiku, returns 3–5 insight bullets
2. A "ICP Insights" card on the leads page — shows after 3+ months of data, hides if insufficient data
3. "Apply this to my ICP" button — pre-fills the ICP form with the recommended changes (confirm before saving)

## PIECE 10 — THE NETWORK EFFECT (BENCHMARKS)

**The vision:** "K.I.N.D clients in Fintech SA average 7.1% reply rate. You're at 11.4%."

**How it actually gets done:**

**The data already exists** across all clients. Aggregating it is a single SQL query. The only challenge is privacy — you must anonymise and aggregate so no individual client's data is identifiable.

**The query:**
```sql
SELECT 
  l.industry,
  l.country,
  ROUND(AVG(CASE WHEN r.reply_classification = 'interested' THEN 1.0 ELSE 0 END) * 100, 1) as avg_reply_rate,
  COUNT(DISTINCT l.client_id) as contributing_clients
FROM leads l
LEFT JOIN figsy_replies r ON r.lead_id = l.id
GROUP BY l.industry, l.country
HAVING COUNT(DISTINCT l.client_id) >= 5  -- minimum 5 clients before showing benchmark
```

The `>= 5` gate means a client can never back-calculate who the others are.

**What's needed:**
1. `GET /benchmarks/reply-rates` — runs aggregation query, returns industry/geo benchmarks
2. Client's own stats vs benchmark shown on FIGSY analytics page
3. Opt-in mechanism in settings (default: opted-in, can opt out)

### 2. Lemlist — The Conversion Machine

Lemlist has built one of the most effective cold outreach products in the market. What to absorb:

**Personalised images in emails**
Lemlist's signature move — they pioneered it. Every email contains an image with the prospect's name, company logo, or LinkedIn photo dynamically inserted. A whiteboard that says *"Hey [First Name], had an idea for [Company]…"* — generated per recipient at send time. Reply rates go up because it's visually arresting. Nobody expects a personalised image in a cold email.

*K.I.N.D version: FIGSY's Day 1 email includes a dynamically generated image — prospect's company name on a mock dashboard, or a result graphic. Not complex — HTML-to-image canvas API. Phase 3.*

**The visual sequence builder**
Lemlist's sequence UI is excellent. Every step laid out visually — Day 1 email, Day 3 LinkedIn, Day 7 follow-up, Day 14 breakup. Delays, conditions, branches all visible at once. Clients currently can't see or change the FIGSY sequence flow at all. Eventually they'll want to — add steps, change delays, create branches.

*K.I.N.D version: This is Piece 8 (Visual Automation Builder) below. Lemlist proves the demand is real.*

**Template library by use case**
Lemlist ships with proven cold email sequences for SaaS, agency, recruiting, consulting. Plug in your company name and you're running in 10 minutes.

*K.I.N.D version: When a client builds an ICP targeting "Fintech CTOs in SA," a pre-built FIGSY sequence for that exact profile loads automatically. The founder doesn't think about tone, length, or cadence. It's already optimised. Phase 2, low effort.*

**Community — "Lemlist Family"**
This is Lemlist's biggest differentiator and the thing most people miss. They built a massive community — templates, playbooks, case studies, weekly newsletters, a Slack group with tens of thousands of members. When someone Googles "cold email template for SaaS" — Lemlist is in the results. They made their product the hub of a community, not just a tool.

*K.I.N.D version: Become the go-to resource for B2B outreach in South Africa and Africa. Nobody owns that space. Blog posts on "how to do B2B outreach in Nigeria," "POPIA and cold email — what's allowed," "best industries to target in SA." Costs nothing, compounds over time. Start now.*

**Multi-channel sequences (email + LinkedIn)**
Lemlist combines email + LinkedIn connection + LinkedIn message in one sequence. K.I.N.D deliberately avoids this — LinkedIn automation is against their ToS and K.I.N.D doesn't build it. But the principle (multi-surface contact over 3 weeks) is right. *This stays off the roadmap unless LinkedIn's ToS changes.*

**What Lemlist has that FIGSY already does better:** AI-generated first lines (Lemlist generates one personalised opener — FIGSY personalises the full email). K.I.N.D wins on depth. Lemlist wins on the image/visual layer. Both are worth having.

### 3. Apollo — Supplier, Competitor, and Teacher

Apollo is the most important company in K.I.N.D's world — simultaneously the data source powering the product, a partial competitor, and the most instructive product to study at scale.

**What Apollo actually is:**
1. Contact database — 275M+ professional contacts. This is what K.I.N.D calls via API to find leads
2. Sequences — DIY outreach automation. This is where Apollo overlaps with FIGSY
3. CRM / pipeline — Deals, calls, Salesforce sync. K.I.N.D doesn't play here yet

**Where K.I.N.D competes:** FIGSY vs Apollo sequences. But Apollo sells a toolbox to in-house SDR teams. K.I.N.D sells a fully managed outcome to founders who have no SDR. Non-overlapping buyers.

**Where K.I.N.D doesn't compete:** Data ownership (Apollo's 10-year database is the raw material, not the competition), enterprise CRM, US/EU enterprise sales tooling.

**What to learn from Apollo:**
- *Job change alerts* — this person just moved companies. Highest intent moment to reach out. Apollo surfaces it. K.I.N.D could show it as a badge on lead cards and auto-prioritise in FIGSY. Apollo API already exposes this data. Phase 4.
- *Sequence analytics* — open rate by subject line, reply rate by day of week, best time to send by industry. K.I.N.D already collects all of this in `figsy_sent_emails`. The Benchmarks feature (Piece 10) is K.I.N.D's Africa-specific version.
- *AI transparency* — show *why* FIGSY wrote an email the way it did. "This email referenced that your target raised Series A. Source: Apollo intent data." Builds trust in the AI. Phase 3 — simple UI change.
- *Multi-channel* — Apollo does email + LinkedIn + phone. FIGSY does email only now. LinkedIn step is Phase 5+.
- *Intent spike signals* — companies researching topics relevant to your product. Requires Bombora/G2 intent data (~$2k/mo). Year 2.

**The strategic reality:** Apollo is primarily a supplier. The genuine risk is if Apollo builds a "Done-For-You" managed service tier targeting African SMEs. Currently not their focus — their roadmap is US/EU enterprise. **The hedge:** the Africa data moat. K.I.N.D's advantage is not the data source — it's what it learns from running thousands of African B2B outreach sequences over time. That dataset is unreplicable regardless of what Apollo builds.

The most strategically interesting piece on this list.

**What it unlocks:** A founder has Claude open and types:
> *"Find me 20 CTOs at fintech companies in Lagos with 50–200 employees."*

Claude calls the K.I.N.D MCP → runs the ICP search → returns scored, POPIA-screened leads → directly in the Claude conversation. No portal login required.

Or an agency building their own AI workflow:
> *"Every Monday, find 50 new leads matching this profile and enroll them in FIGSY sequence 3."*

Their AI agent calls the K.I.N.D MCP on a schedule. Fully automated. No human in the loop.

**Tools the MCP server would expose:**

| Tool | What it does |
|---|---|
| `search_leads` | Run an ICP search — returns scored, filtered contacts |
| `get_leads` | Fetch existing leads with filters |
| `create_icp` | Create a new ICP profile |

| `get_figsy_stats` | FIGSY campaign performance — sent, opens, replies, interested |

All of these map to API endpoints that already exist. The MCP server is a structured wrapper around the existing REST API.
