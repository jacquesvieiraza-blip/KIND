## 4. EVERY TECHNICAL DECISION

### Architecture Decisions
- **Monorepo pattern**: Turborepo with yarn workspaces (single lock file, efficient caching)
- **Deployment**: Railway auto-detects `apps/*` and `packages/*` structure
- **Frontend router**: Next.js 14 App Router (searchParams = plain object, not Promise like Next.js 15)
- **Backend**: Express.js with TypeScript strict mode
- **Database**: Supabase PostgreSQL with RLS policies per table
- **Authentication**: JWT from Supabase Auth on every request
- **Error handling**: Try/catch (no .catch() on Supabase PromiseLike)

### Database Decisions
- **RLS policies**: Each client sees only their own data
- **Versioned migrations**: SQL files from 20260511 through 20260527
- **Indexes**: Foreign keys + unique constraints + compound indexes on filters
- **Backup**: Daily automated, 30-day retention
- **Replication**: Standby enabled for high availability

### Frontend Decisions
- **Dark mode**: `darkMode: 'class'` + localStorage key `kind_theme` + inline &lt;script&gt; prevents FOUC
- **Icons**: Lucide React (most UI) + inline SVG for agent avatars
- **Forms**: React Hook Form + Zod validation (type-safe)
- **Rate limiting**: Express-rate-limit on public endpoints (Vida widget, lead consent)
- **CORS**: `*.railway.app` wildcard for Railway-deployed frontends

### API Design
- **Auth middleware**: JWT verification from Supabase; `requireAuth` wraps protected routes
- **Webhooks**: Resend (FIGSY inbound), Stripe (payments), Smartsheet (future)
- **Cron jobs**: 19 scheduled tasks using node-cron (5min, hourly, daily, weekly)
- **Error responses**: Structured JSON with HTTP status codes

### Performance Optimizations
- **Lead scoring batching**: One Claude call per 10 leads (10× cost reduction)
- **Database query optimization**: Indexes on `(client_id, status)` for fast filtering
- **Cron scheduling**: Staggered times (10:00, 10:08, 07:40) to avoid thundering herd
- **Frontend code splitting**: Route-based with Next.js dynamic imports
- **Image optimization**: `next/image` with lazy loading

### Security Measures
- **Environment variables**: Never logged, never shown in UI; separate public/private
- **JWT verification**: On every API request
- **RLS policies**: Table-level security gated by `auth.uid()`
- **CSRF protection**: Next.js middleware
- **Webhook verification**: Stripe signature + Resend secret header checked
- **SQL injection prevention**: Parameterized queries (no raw concatenation)
- **Data encryption**: TLS 1.2+ in transit, Supabase encryption at rest

### Integration Patterns
- **Apollo.io**: Auth via API key; 1 req/5 sec rate limit; 3-pass fallback search
- **Resend**: Auth via API key; webhook URL registered in dashboard; RESEND_WEBHOOK_SECRET header check
- **Stripe**: Secret key auth; checkout session creation; webhook signature verification
- **Claude**: API key auth; batch scoring (10 leads/call); structured JSON responses
